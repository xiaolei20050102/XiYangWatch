## 一、为什么发明 I2C

### 1.1 并口时代的痛点

1980 年代初，飞利浦（现恩智浦 NXP）的工程师面临一个问题：一块 PCB 上要连 EEPROM、ADC、DAC、RTC……七八个芯片，每个用并口需要 8 根数据线 + 控制线，上百根走线，MCU 引脚根本不够。

### 1.2 I2C 的答案：两根线，喊名字

```
传统并口：                          I2C：
  MCU ── 8根 ── 芯片A               
      ── 8根 ── 芯片B                      SDA ────────────────
      ── 8根 ── 芯片C               MCU    ├── 芯片A           │
      ── CS1 ── 芯片A                      ├── 芯片B
      ── CS2 ── 芯片B               SCL ──┼── 芯片C
      ── CS3 ── 芯片C                      └── ...
      50+ 根线                              2 根线，挂 127 个设备
```

I2C = **I**nter-**I**ntegrated **C**ircuit（集成电路间总线）。核心思想：所有设备共用一对线，靠地址区分。

## 二、物理层：两根线的硬件真相

### 2.1 每个设备的引脚内部结构

I2C 设备在 SCL/SDA 引脚内部**只有一个 NMOS 管**，没有 PMOS：

```
         引脚
          │
    ┌─────┴─────  ← 连到内部电路（施密特触发器，用于读电平）
    │
   NMOS ← 栅极由内部控制
    │
   GND
```

这意味着设备只能做两件事：
- **NMOS 关断（释放）**：引脚处于高阻态，什么都不做
- **NMOS 导通（拉低）**：引脚强行拉到 GND

**没有任何设备能"主动输出高电平"。** 这是 I2C 最核心的硬件特性。

### 2.2 上拉电阻：高电平的唯一来源

既然没人能主动推高，高电平从哪来？**外部上拉电阻。**

```
                    VDD (3.3V)
                       │
                     4.7kΩ   ← 焊在 PCB 上
                       │
                       ├──── SDA / SCL
                       │
      所有设备的 NMOS ──┴── 全部关断时
                           电阻把线拉到高
```

整条总线只需要**两个电阻**（SDA 各一个，SCL 各一个），不管上面挂了多少设备。

### 2.3 开漏 + 上拉的好处：天然防短路

```
如果设备 A 用推挽输出高电平，设备 B 同时拉低：

    VDD
     │
   PMOS(导通)──┐
     │         │
     ├── SDA ──┤
     │         │
   NMOS(关断)   NMOS(导通)
     │         │
    GND       GND
   设备A      设备B

结果：VDD → PMOS → NMOS → GND，直接短路！几十 mA 电流可能烧毁引脚。
```

```
开漏 + 上拉，同样场景：

    VDD
     │
   4.7kΩ
     │
     ├── SDA ──┤
     ×         │
   NMOS      NMOS(导通)    ← 只有设备 B 拉低
     ×         │
    GND       GND

电流 = 3.3V / 4.7kΩ ≈ 0.7mA，完全安全。
上拉电阻是"弱"的（mA 级以下），NMOS 是"强"的（几十 mA），
谁都可以轻松把线拉低，上拉那点电流构不成威胁。
```

这就是为什么 I2C 允许多个设备安全地共用同一条线——物理层天然防冲突。

### 2.4 两条线的分工

| 线 | 全称 | 方向 | 谁控制 |
|----|------|:--:|--------|
| **SCL** | Serial Clock | 单向 | **永远只有主机** |
| **SDA** | Serial Data | 双向 | 主机和从机轮流控制 |

**SCL 的角色：** 主机敲节拍，所有从机跟着节奏走。SCL 不动，时间就不走——从机不会主动催主机。I2C 协议没有规定 SCL 脉冲间隔的最大值，主机可以在两个脉冲之间想隔多久隔多久。

## 三、协议层：五个核心信号

整个 I2C 协议由五种基本信号组成。记住它们，协议就通了。

### 3.1 数据位（Data Bit）

```
SCL:  ────┐     ┌─────
          │     │
SDA:  ────┘─────┘─────   ← SCL 低时设好 SDA 的值
          │     │
          └─────┘
           ↓     ↑
        设数据   采样

规则：SCL 低时 → SDA 可以变（设数据位）
      SCL 高时 → SDA 必须稳定，从机在上升沿采样
```

一个时钟脉冲传 1 位。8 个脉冲 = 1 字节。

### 3.2 START（起始信号）

```
SCL:  ━━━━━━━━━━━━━━━━━
               │
SDA:  ━━━━━━━╲
              ╲__________
               │
          SCL 高时，SDA 高→低

含义："所有人注意！我要说话了！"
      所有从机收到 START 后，内部比特计数器清零，准备收地址。
```

### 3.3 STOP（停止信号）

```
SCL:  ━━━━━━━━━━━━━━━━━
               │
SDA:  __________╱
               ╱
               │
          SCL 高时，SDA 低→高

含义："通话结束，总线释放。"
```

### 3.4 ACK（应答）

```
第 9 个 SCL 脉冲：

SCL:  ────┐     ┌─────
          │     │
SDA:  ────┘─────┘─────   ← 接收方在第 9 拍拉低 SDA = ACK
          │     │
          └─────┘
          采样 ACK

ACK  = SDA 被拉低 = "收到了，继续"
NACK = SDA 保持高 = "没收到"或"够了，别发了"
```

**谁发 ACK？**
- 主机发地址/数据 → 从机回 ACK
- 从机发数据 → 主机回 ACK（表示继续要）或 NACK（表示够了）

### 3.5 RESTART（重复起始）

```
时序和 START 一模一样（SCL 高时 SDA 高→低），但出现在帧中间而非开头。

与 STOP + START 的区别：
  STOP + START：释放总线 → 重新抢占，其他设备可能插队
  RESTART：      不释放总线，保证原子操作

典型用途：读寄存器的"先写后读"操作（见下文）。
```

### 3.6 为什么 START/STOP 能作为特殊信号

START 和 STOP 故意**违反**数据位的规则：

```
正常数据位：SCL 低时 SDA 变化，SCL 高时 SDA 稳定
START/STOP：SCL 高时 SDA 变化 ← 故意犯规

从机硬件状态机检测到"SCL 高 + SDA 边沿"就知道这不是数据，是帧边界。
```

## 四、完整通信帧

### 4.1 基本帧结构

```
S → [地址 + R/W] → A → [数据1] → A → [数据2] → A → ... → P

图例：
  S  = START
  P  = STOP
  A  = ACK
  N  = NACK
  [ ] = 主机发
  [粗] = 从机发
```

永远 **① START 开头** → **② 第一个字节是地址 + 方向** → **③ 后面跟 N 字节数据** → **④ STOP 结尾**。

每字节 8 位 + 1 位 ACK，共 9 个 SCL 脉冲。

### 4.2 STOP 的时序细节

STOP 的本质是"SCL 高时，SDA 低→高"。无论 SDA 当前是什么状态，都先确保 SCL 低 → SDA 拉低 → SCL 拉高 → SDA 拉高：

```
安全的 STOP 流程：
① SCL 拉低       ← 先确保在安全区
② SDA 拉低       ← SCL 低时，SDA 怎么变都行
③ SCL 拉高       ← SCL 先高
④ SDA 拉高       ← SDA 低→高，SCL 高时 → STOP ✓

如果在 SCL 高时直接把 SDA 拉低 → 变 START 了！
先拉低 SCL 是保命操作。
```

## 五、寻址机制

### 5.1 7 位地址

I2C 标准地址是 7 位，范围 0x00~0x7F（127 个地址）。部分地址保留（如 0x00 是广播地址）。

### 5.2 7-bit vs 8-bit 地址

```
START 后的第一个字节：

  bit7  bit6  bit5  bit4  bit3  bit2  bit1  bit0
 [             7 位地址             ][  R/W  ]
                                     0 = 写
                                     1 = 读

示例：CST816S 地址 0x15 = 0b0010101

  写操作：0b0010101 0 = 0x2A
  读操作：0b0010101 1 = 0x2B
```

### 5.3 为什么 HAL 让你传左移后的地址

STM32 的 I2C 硬件寄存器 `I2C_CR2` 期望地址左对齐到 bit7:1：

```
I2C_CR2 寄存器：
  bit7  bit6  bit5  bit4  bit3  bit2  bit1  bit0
 [              7 位地址            ][ 保留，硬件填 R/W ]
```

HAL 库选择了"贴近硬件"的设计——你传 `(0x15 << 1) = 0x2A`，HAL 直接写寄存器，不做转换：

```c
#define CST816_ADDR_8BIT  ((0x15) << 1)    // = 0x2A

HAL_I2C_Mem_Write(..., CST816_ADDR_8BIT, ...);  // HAL 原样发 0x2A（写）
HAL_I2C_Mem_Read(..., CST816_ADDR_8BIT, ...);   // HAL 内部 | 1 → 0x2B（读）
```

**结论：统统传左移后的写地址，HAL 根据函数名自动处理读写位。**

### 5.4 10 位地址

I2C 也支持 10 位地址（扩展 1024 个地址），兼容 7 位设备。用第一个字节的 `0b11110XXX` 前缀标识。本项目不使用，细节略。

## 六、主机写 vs 主机读

### 6.1 写操作（一气呵成）

例：向 CST816S 寄存器 `0xF9` 写入 `0x05`

```
S → [0x2A] → A → [0xF9] → A → [0x05] → A → P
    └─地址─┘     └─寄存器号─┘  └─数据─┘

① START — "所有人注意"
② 发 0x2A（地址 0x15 + 写）→ 从机 ACK — "我是 0x15，听到了"
③ 发 0xF9（寄存器号）→ 从机 ACK — "寄存器 0xF9，收到"
④ 发 0x05（要写的值）→ 从机 ACK — "写好了"
⑤ STOP — "结束"
```

### 6.2 读操作（先写后读，中间不掉头）

例：从 CST816S 寄存器 `0x03` 读 4 字节坐标

```
S → [0x2A] → A → [0x03] → A → Sr → [0x2B] → A → [数据0] → A → [数据1] → A → [数据2] → A → [数据3] → N → P
    └─写地址─┘    └─寄存器号─┘   └─读地址─┘   └────── 从机发数据 ──────────┘

① START
② 发 0x2A（写）→ ACK
③ 发 0x03（寄存器号）→ ACK
④ RESTART（不是 STOP！不释放总线）
⑤ 发 0x2B（读）→ ACK
⑥ 从机发数据 [0] → 主机回 ACK（"继续"）
⑦ 从机发数据 [1] → 主机回 ACK（"继续"）
⑧ 从机发数据 [2] → 主机回 ACK（"继续"）
⑨ 从机发数据 [3] → 主机回 NACK（"够了"）
⑩ STOP
```

### 6.3 为什么先写后读

从机内部有一个**寄存器地址指针**：

```
第一次写 0x03：从机把内部指针 REG_PTR 设为 0x03
RESTART 后读：  从机从 REG_PTR 指向的寄存器开始往外吐数据

就像文件操作：先 fseek() 定位，再 fread() 读取。
```

RESTART 不会清空指针——所以可以先写寄存器号，再读数据。如果用了 STOP，指针可能重置。

### 6.4 地址自增

CST816S 支持地址自增——每读一个字节，内部指针自动 +1。所以从 0x03 开始读 4 字节，实际读到的是 0x03 → 0x04 → 0x05 → 0x06。

不是所有设备都支持自增。不支持的设备需要分 4 次调用：

```c
// 不支持自增时，必须每次指定不同寄存器号
TOUCH_I2C_READ(0x03, &buf[0], 1);
TOUCH_I2C_READ(0x04, &buf[1], 1);
TOUCH_I2C_READ(0x05, &buf[2], 1);
TOUCH_I2C_READ(0x06, &buf[3], 1);
```

## 七、多设备总线

### 7.1 原理

所有设备并联在同一条 SCL 和 SDA 上：

```
              VDD               VDD
               │                 │
             4.7kΩ             4.7kΩ
               │                 │
  MCU ──────── SCL ────┬─────── SDA ────────
               │       │         │
         ┌─────┼──┐   ┌┼──┐  ┌──┼─────┐
         │ 从机① │   │从机②│  │ 从机③  │
         │0x15  │   │0x6A │  │ 0x76  │
         └────────┘   └────┘  └────────┘
```

- 谁想通信，先发地址。只有地址匹配的从机才响应
- 其余从机全程无视
- 同一时刻只能有一个主机控制总线

### 7.2 多个设备都有上拉电阻

如果每个从机模块都自带 4.7kΩ 上拉：

```
3 个模块并联：4.7kΩ ∥ 4.7kΩ ∥ 4.7kΩ ≈ 1.57kΩ
5 个模块并联：4.7kΩ ∥ 4.7kΩ ∥ 4.7kΩ ∥ 4.7kΩ ∥ 4.7kΩ ≈ 0.94kΩ  ← 危险
```

| 模块数 | 等效上拉 | 拉低电流 | 状态 |
|:-----:|:--------:|:--------:|:----:|
| 1 | 4.7kΩ | 0.7mA | ✅ |
| 2~3 | 2.3~1.6kΩ | 1.4~2.1mA | ✅ |
| 4~5 | 1.2~0.94kΩ | 2.8~3.5mA | ⚠️ |
| 6+ | <0.8kΩ | >4mA | ❌ |

**集成到一张 PCB 时：只焊一对上拉电阻，各从机不焊上拉。模块化开发时每个模块自带，2~3 个问题不大。**

## 八、硬件 I2C vs 软件模拟 I2C

### 8.1 硬件 I2C

STM32 内部有专门的 I2C 外设，你只需配置寄存器，剩下的全自动：

```c
HAL_I2C_Mem_Read(&hi2c1, 0x2A, 0x03, I2C_MEMADD_SIZE_8BIT, buf, 4, 100);
//                ↑       ↑     ↑          ↑                 ↑   ↑
//              外设   设备地址 寄存器号  寄存器号位数       缓冲区 超时
//
// 这一个函数调用，硬件自动完成：
// START → 发地址 → ACK → 发寄存器号 → ACK → RESTART → 发读地址 → ACK
// → 收4字节数据 → NACK → STOP
// 全程无需 CPU 干预（可配合 DMA）
```

**优点：** CPU 负担低，时序精确，代码简洁  
**缺点：** STM32 的硬件 I2C 出了名的 buggy（尤其是 F1 系列），调试困难

### 8.2 软件模拟 I2C（Bit-Banging）

纯用 GPIO 手动拉高拉低来模拟时序，不走硬件外设：

```c
// 软件 I2C 的核心：SDA 动态切方向
#define SDA_IN()    GPIO_MODE_INPUT       // 切输入 → 准备读
#define SDA_OUT()   GPIO_MODE_OUTPUT_PP   // 切输出 → 准备写

// 发一个字节
for (int i = 0; i < 8; i++) {
    SCL_Clr();           // SCL 低
    if (byte & 0x80)     // 设 SDA
        SDA_Set();
    else
        SDA_Clr();
    SCL_Set();           // SCL 高 → 从机采样
    byte <<= 1;
}

// 收 ACK
SDA_IN();                // 切输入，释放 SDA
SCL_Set();               // 第 9 个脉冲
ack = SDA_Get();         // 读 ACK
SCL_Clr();
SDA_OUT();               // 切回输出
```

**判断是软件模拟 I2C 的标志：有 `SDA_IN()` / `SDA_OUT()` 宏。** 硬件 I2C 不需要，因为硬件自动管理方向。

**优点：** 不依赖硬件外设，任意 GPIO 都能用，方便调试  
**缺点：** 占用 CPU 时间，速度慢，时序靠延时精确度差

### 8.3 本项目用哪个

**硬件 I2C1。** CST816S 驱动通过 HAL 库封装，没有一行手动敲 SCL 的代码。

## 九、本项目 I2C 总览

### 9.1 I2C1 总线设备

```
I2C1 (PB6=SCL, PB7=SDA, 100kHz 标准模式)
│
├── 0x15  CST816S    触摸屏控制器
├── 0x6A  QMI8658    6 轴 IMU（加速度 + 陀螺仪）
├── 0x57  MAX30102   心率血氧传感器
├── 0x76  BME280     温度 / 湿度 / 气压
└── 0x68  DS3231     RTC 实时时钟
```

5 个传感器共用 PB6/PB7 两根线。

### 9.2 CST816S 驱动接口

```c
// 硬件抽象宏（在 touch_cst816s.h 中定义，移植只需改这里）
#define TOUCH_I2C_WRITE(reg, pData, sz) \
    HAL_I2C_Mem_Write(&hi2c1, 0x2A, (reg), I2C_MEMADD_SIZE_8BIT, (pData), (sz), 100)

#define TOUCH_I2C_READ(reg, pData, sz) \
    HAL_I2C_Mem_Read(&hi2c1, 0x2A, (reg), I2C_MEMADD_SIZE_8BIT, (pData), (sz), 100)

// 驱动对外接口
void    CST816_Init(void);                    // 硬件复位 + 配休眠
uint8_t CST816_GetFingerNum(void);           // 手指在不在
void    CST816_GetTouch(Touch_Info_t* info); // 读坐标（已加偏移）
void    CST816_Sleep(void);                   // 软件休眠
void    CST816_Wakeup(void);                  // 硬件复位唤醒
```

### 9.3 FreeRTOS 互斥注意事项

I2C1 被多个传感器共用。如果多个 FreeRTOS 任务同时访问 I2C1（比如：

- LVGL 任务每 5ms 读 CST816
- 传感器任务每 100ms 读 BME280
- 心率任务每 10ms 读 MAX30102

就需要加互斥锁（Mutex）保护 HAL I2C 调用不被打断，否则会出现总线冲突。

**本项目当前 LVGL 任务独占 I2C1（其他传感器尚未接入任务调度），暂时不需要 mutex。**

## 十、常见问题与踩坑

### Q1：为什么 SCL 高时 SDA 不能变？

因为从机在 SCL 上升沿采样 SDA。如果 SDA 此时正在跳变，从机可能读到错误的值（0 和 1 之间的中间电平）。

### Q2：ACK 是谁发给谁的？

**8 位数据发出后，接收方回 ACK。**
- 主机发数据 → 从机回 ACK
- 从机发数据 → 主机回 ACK（或 NACK 表示"够了"）

第九个 SCL 脉冲的 SDA 方向和数据相反。

### Q3：总线上一堆设备怎么不冲突？

- 只有地址匹配的从机才响应
- NMOS 开漏结构保证多人拉低不短路
- SCL 由主机单独控制，从机不碰

### Q4：为什么有的设备用硬件 I2C 有的用软件模拟？

- 硬件 I2C：引脚支持 I2C 复用功能（STM32 某些引脚不能映射到 I2C 外设）
- 软件模拟：任意 GPIO 都能用，但 CPU 开销大
- 有些 MCU 的硬件 I2C 有硅级 bug，只能软件模拟

### Q5：上拉电阻大小有什么讲究？

| 电阻值 | 上拉电流 | 上升时间 | 适用场景 |
|:------:|:--------:|:--------:|----------|
| 1.5kΩ | 2.2mA | 快 | 400kHz 快速模式 |
| 4.7kΩ | 0.7mA | 中 | **标准 100kHz（本项目使用）** |
| 10kΩ | 0.33mA | 慢 | 低速、低功耗场景 |

总线上设备越多 → 寄生电容越大 → 需要更小的上拉电阻来保证上升沿斜率。

## 速记卡

| 概念 | 一句话 |
|------|--------|
| **物理层** | 两个 NMOS + 外部上拉，只能拉低不能推高 |
| **SCL** | 时钟线，永远只有主机控制，从机不碰 |
| **SDA** | 数据线，主机和从机轮流控制 |
| **START** | SCL 高时，SDA 高→低 |
| **STOP** | SCL 高时，SDA 低→高 |
| **RESTART** | = START，但不出让总线 |
| **数据位** | SCL 低时设 SDA，SCL 高时采样 |
| **ACK** | 接收方在第 9 拍拉低 SDA = "收到" |
| **NACK** | SDA 保持高 = "没收到/够了" |
| **地址** | 7 位，第一个字节的高 7 位，bit0 = R/W |
| **8-bit 地址** | 7 位左移 1 位，HAL 库用这个 |
| **读操作** | 先写（发寄存器号）→ RESTART → 再读 |
| **写操作** | 发地址 + 发数据，一气呵成 |
| **地址自增** | 连续读时芯片内部寄存器指针自动 +1 |
| **硬件 I2C** | STM32 外设自动完成，一个 HAL 调用搞定 |
| **软件 I2C** | 手动 GPIO，有 `SDA_IN()`/`SDA_OUT()` 宏切换方向 |
| **多设备** | 共用两根线，靠地址区分，开漏天然防冲突 |
| **上拉电阻** | 整条总线只焊一对（或每个模块自带，并联后 ≥1kΩ） |
