# 02 — CST816S 触摸驱动原理与 I2C 通信详解

> 前置知识：了解 I2C 协议基础（可参考 [03_I2C通信协议详解](./03_I2C通信协议详解.md)），不了解也可以先看本文再回头补。

---

## 一、整体图景

CST816S 是一颗电容触摸控制器芯片，内部有自己的 MCU 和固件。你只需要通过 I2C 读它的寄存器，它替你完成电容检测、坐标计算、手势识别。

```
┌──────────┐    电容变化    ┌──────────────────┐    I2C (2线)    ┌──────────┐
│  你的手指  │ ────────────→ │    CST816S 芯片    │ ←───────────→ │  STM32   │
│          │               │  (内置MCU+固件)    │  SCL + SDA    │ F411CE   │
└──────────┘               │                   │               └──────────┘
                           │ · 自电容检测       │
                           │ · 触摸坐标计算     │
                           │ · 手势识别         │
                           │ · 结果写入寄存器   │
                           └───────────────────┘
```

和 ST7789 的核心区别：**ST7789 是输出设备**（你告诉它画什么），**CST816S 是输入设备**（它告诉你摸哪里）。

## 二、硬件连接

### 2.1 引脚定义

```
STM32F411CE              CST816S 模组
──────────              ────────────
  PB6 (SCL) ──────────── SCL        ← I2C 时钟
  PB7 (SDA) ──────────── SDA        ← I2C 数据
  PB8       ──────────── RST        ← 硬件复位
  PB2       ←─────────── INT        ← 触摸中断（有触摸时拉低）
  
  模组 PCB 上自带 4.7kΩ 上拉电阻（SCL/SDA 各一个）
```

### 2.2 三根控制线的角色

| 引脚 | 方向 | 作用 |
|------|:----:|------|
| **SCL** | 主机→从机 | I2C 时钟，主机敲节拍，从机跟节奏 |
| **SDA** | 双向 | I2C 数据，主机和从机轮流控制 |
| **RST** | 主机→从机 | 硬件复位，拉低 10ms 再拉高让芯片重启 |

INT 引脚本项目未使用——我们改用轮询方式读触摸状态。

## 三、I2C 通信速览

> 完整原理见 [03_I2C通信协议详解](./03_I2C通信协议详解.md)，这里只讲和 CST816S 直接相关的部分。

### 3.1 设备地址

CST816S 的 7 位 I2C 地址 = **0x15**。

HAL 库要求传 8 位地址（7 位左移 1 位）：
```
7-bit 地址:  0x15  = 0b0010101
8-bit 写地址: 0x15 << 1 = 0x2A = 0b00101010
8-bit 读地址: HAL 内部自动把 bit0 置 1 → 0x2B = 0b00101011
```

```c
#define CST816_ADDR        0x15              // 7-bit 地址（手册标注值）
#define CST816_ADDR_8BIT   ((CST816_ADDR) << 1)  // HAL 用的 8-bit 形式
```

你调用 `HAL_I2C_Mem_Write` 时传 `0x2A`，HAL 原样发出（写方向）。调用 `HAL_I2C_Mem_Read` 时也传 `0x2A`，HAL 内部自动 `| 1` 变成 `0x2B`（读方向）。**只需传写地址，HAL 帮你区分读写。**

### 3.2 本项目 I2C1 总线上的设备

```
I2C1 (PB6=SCL, PB7=SDA)
├── 0x15  CST816S   触摸
├── 0x6A  QMI8658   姿态传感器
├── 0x57  MAX30102  心率血氧
├── 0x76  BME280    温湿气压
└── 0x68  DS3231    RTC 时钟
```

**5 个设备共用 2 根线**——I2C 最大的优势。

### 3.3 硬件 I2C vs 软件模拟 I2C

本项目使用 STM32 的 **硬件 I2C1** 外设，HAL 库封装：

```c
// 写寄存器：HAL 自动完成 START → 地址 → 寄存器号 → 数据 → STOP
TOUCH_I2C_WRITE(reg, pData, sz);

// 读寄存器：HAL 自动完成 START → 地址(写) → 寄存器号 → RESTART → 地址(读) → 收数据 → STOP
TOUCH_I2C_READ(reg, pData, sz);
```

一个宏调用搞定全部时序，不需要手动敲 SCL、切 SDA 方向。

### 3.4 HAL Mem 函数参数含义

```c
HAL_I2C_Mem_Read(
    &hi2c1,                    // 使用 I2C1 外设
    0x2A,                      // 设备 8-bit 地址（HAL 内部处理读写位）
    0x03,                      // 要读的寄存器号
    I2C_MEMADD_SIZE_8BIT,      // 寄存器号占 1 字节（8 位）
    buf,                       // 数据缓冲区指针
    4,                         // 读 4 字节
    100                        // 超时 100ms
);
```

`I2C_MEMADD_SIZE_8BIT` 表示寄存器号是 8 位的（范围 0x00~0xFF）。如果芯片寄存器地址是 16 位的（如大容量 EEPROM），改用 `I2C_MEMADD_SIZE_16BIT`。

## 四、寄存器模型

CST816S 和 ST7789 一样采用"寄存器模型"——你通过读写寄存器来和它交互。

### 4.1 关键寄存器一览

| 地址 | 名称 | 读写 | 作用 |
|:----:|------|:--:|------|
| `0xA7` | ChipID | 读 | 芯片 ID，应为 0xB4~0xB6，验证通信正常 |
| `0x02` | FingerNum | 读 | 当前手指数量：`0x00`=没摸，`0xFF`=睡眠，`>=1`=有手指 |
| `0x03` | XposH | 读 | X 坐标高字节（高 4 位是事件标志，低 4 位是坐标高 4 位） |
| `0x04` | XposL | 读 | X 坐标低 8 位 |
| `0x05` | YposH | 读 | Y 坐标高字节（高 4 位是触摸 ID，低 4 位是坐标高 4 位） |
| `0x06` | YposL | 读 | Y 坐标低 8 位 |
| `0x01` | GestureID | 读 | 硬件手势（读后自动清零，不可靠，本项目不使用） |
| `0xE5` | SleepMode | 写 | 写 `0x03` 进入睡眠模式 |
| `0xF9` | AutoSleepTime | 写 | N 秒无触摸后自动进入低功耗 |

### 4.2 坐标寄存器细节

坐标是 12 位的（0~4095），芯片内部已经映射到面板分辨率，分拆成两个 8 位寄存器存储：

```
寄存器 0x03 (XposH):  [E3 E2 E1 E0 | X11 X10 X9 X8]
                      └─ 事件标志 ─┘ └─ X坐标高4位 ─┘

寄存器 0x04 (XposL):  [ X7  X6  X5  X4 | X3  X2  X1  X0]
                      └──────── X坐标低8位 ─────────────┘

寄存器 0x05 (YposH):  [I3 I2 I1 I0 | Y11 Y10 Y9 Y8]
                      └─ 触摸ID ──┘ └─ Y坐标高4位 ─┘

寄存器 0x06 (YposL):  [ Y7  Y6  Y5  Y4 | Y3  Y2  Y1  Y0]
                      └──────── Y坐标低8位 ─────────────┘
```

代码拼接坐标：

```c
void CST816_GetTouch(Touch_Info_t* info)
{
    uint8_t buf[4] = {0};
    TOUCH_I2C_READ(REG_XposH, buf, 4);  // 从 0x03 开始连续读 4 字节

    info->X_Pos = (((buf[0] & 0x0F) << 8) | buf[1]) + TOUCH_OFFSET_X;
    info->Y_Pos = (((buf[2] & 0x0F) << 8) | buf[3]) + TOUCH_OFFSET_Y;
}
```

逐步拆解：
```
buf[0] & 0x0F     → 干掉高 4 位事件标志，只留坐标高 4 位
<< 8              → 左移 8 位，变成结果的 bit11:8
| buf[1]          → 拼上低 8 位 = 完整的 12 位 X 坐标
+ TOUCH_OFFSET_X  → 叠加面板偏移补偿
```

**为什么能一口气读 4 字节？** CST816S 支持地址自增——读完 0x03 后内部指针自动跳到 0x04，再跳到 0x05、0x06。不是所有 I2C 设备都支持，要看芯片手册。

## 五、触摸面板偏移校准

### 5.1 为什么需要偏移

触摸面板和 LCD 屏幕是两块独立硬件叠在一起的，物理对齐存在误差。偏移量就是拿来补偿这个误差的。

```
手指点屏幕 (0, 0) ──→ 触摸面板感应到的位置可能是 (2, 5)
                         ↓ +TOUCH_OFFSET_X=2, +TOUCH_OFFSET_Y=5
                    修正为 (2, 5) ≈ 屏幕 (0, 0)
```

### 5.2 当前配置

```c
#define TOUCH_OFFSET_X  0   // X 轴偏移（无补偿）
#define TOUCH_OFFSET_Y  0   // Y 轴偏移（经实测无需补偿）
```

这两个值经校准函数 `CST816_Calibrate()` 实测确定。换模组或换厂家时需重新校准。

### 5.3 如何校准

详见 `touch_cst816s.c` 中的 `CST816_Calibrate()` 函数。原理：

1. 用 `CST816_GetTouchRaw()` 读取原始坐标（不叠加偏移）
2. 手指触摸屏幕四角和中心的已知位置
3. 串口打印原始坐标
4. 计算公式：`offset = 屏幕坐标 − 原始坐标`
5. 5 个点取平均值，填入 `TOUCH_OFFSET_X` / `TOUCH_OFFSET_Y`

## 六、初始化流程

```c
void CST816_Init(void)
{
    /* 硬件复位 */
    TOUCH_RST_LOW();        // RST 拉低
    TOUCH_DELAY_MS(10);     // 保持 10ms（芯片复位）
    TOUCH_RST_HIGH();       // RST 拉高
    TOUCH_DELAY_MS(100);    // 等 100ms（芯片内部初始化完成）

    /* 5 秒无触摸自动进入低功耗 */
    uint8_t t = 5;
    TOUCH_I2C_WRITE(REG_AutoSleepTime, &t, 1);
}
```

初始化只做两件事：**硬件复位** + **配置自动休眠时间**。比 ST7789 简单得多——触摸芯片不需要配置一堆电压、Gamma、时序参数。

### 为什么休眠后必须用 RST 唤醒而不用 I2C

CST816S 深度休眠后，内部振荡器停摆，I2C 接口关闭，发任何 I2C 命令它都听不见。只有拉 RST 引脚——纯硬件信号——能把它强制唤醒。

```c
void CST816_Wakeup(void)
{
    TOUCH_RST_LOW();
    TOUCH_DELAY_MS(10);
    TOUCH_RST_HIGH();
    TOUCH_DELAY_MS(100);
}
```

## 七、与 LVGL 的衔接

### 7.1 数据流向

```
CST816S 硬件
    │
    ├── CST816_GetFingerNum() → 手指在不在？
    │       ↓
    │   lv_port_indev.c: touchpad_is_pressed()
    │
    └── CST816_GetTouch()   → 坐标（已叠加 TOUCH_OFFSET）
            ↓
        lv_port_indev.c: touchpad_get_xy()
            ↓
        LVGL indev 输入设备
            ↓
        LVGL 事件系统（click / press / release / drag）
```

### 7.2 触摸状态判定

```c
static bool touchpad_is_pressed(void)
{
    uint8_t finger = CST816_GetFingerNum();
    return (finger != 0x00 && finger != 0xFF);
    //      没摸               在睡觉        都不是 = 正在摸
}
```

### 7.3 坐标直接喂给 LVGL

```c
static void touchpad_get_xy(int32_t *x, int32_t *y)
{
    Touch_Info_t info;
    CST816_GetTouch(&info);   // 已经包含偏移补偿
    *x = (int32_t)info.X_Pos;
    *y = (int32_t)info.Y_Pos;
}
```

LVGL indev 层不做任何额外缩放或校准——偏移在 `CST816_GetTouch()` 内部已经处理好了。

## 八、手势检测：为什么不用芯片自带的

CST816S 硬件手势寄存器 `0x01` 号称能直接返回 CLICK / DOUBLECLICK / LONGPRESS / UP / DOWN / LEFT / RIGHT。

**实测结论：滑动和长按基本可靠，单击和双击不可靠。**

原因：
- 手势寄存器读后自动清零，固件内部判断逻辑不稳定
- 不同批次芯片的固件版本差异大
- 同一寄存器在一次触摸期间持续报告同一个值，需自己处理去重

### 本项目采用 OV-Watch 方案

驱动层只提供两个接口，手势判断交给应用层：

```c
CST816_GetFingerNum();   // 手指在不在？
CST816_GetTouch(&info);  // 在哪？
```

上层通过时间差 + 坐标差判断手势：

```
两次按下 < 400ms → 双击
按住 > 600ms    → 长按
ΔX > ΔY 且 > 阈值 → 左右滑动
ΔY > ΔX 且 > 阈值 → 上下滑动
```

LVGL 接入后，大部分手势（点击、滑动、长按）由 LVGL 的事件系统自动处理。

## 九、踩过的坑

| 坑 | 现象 | 原因 | 解决 |
|----|------|------|------|
| **手势寄存器不可靠** | 双击检测不到，单击误报 | CST816S 硬件手势固件不稳定 | 改用只读手指数 + 坐标 |
| **同一手势重复触发** | 一次触摸打印几十条 | 寄存器值在一次触摸期间持续不变 | 加状态去重（检测边沿，不检测电平） |
| **休眠判据过严** | 唤醒后自检 FAIL | 部分芯片休眠后 FingerNum 返回 0x00 而非 0xFF | 放宽判据，能唤醒就算通过 |
| **运算符优先级** | X 偏移加法可能挂到 buf[1] 上而不是整个坐标 | `\|` 优先级低于 `+` | 加括号：`((...) \| buf[1]) + OFFSET` |

## 十、完整数据流

```
上电
 │
 ├─ CST816_Init()
 │   ├─ RST 拉低 10ms → 拉高 100ms（硬件复位）
 │   └─ I2C 写 0xF9 ← 5（5秒无触摸休眠）
 │
 └─ FreeRTOS LVGL 任务循环 (每 5ms)
     │
     ├─ lv_timer_handler() 内部调用 touchpad_read()
     │   ├─ CST816_GetFingerNum() → 手指数
     │   │   ├─ 0x00 → 没摸 → LVGL RELEASED
     │   │   ├─ 0xFF → 在睡觉 → LVGL RELEASED
     │   │   └─ ≥0x01 → 有手指 → LVGL PRESSED
     │   │
     │   └─ CST816_GetTouch(&info)
     │       ├─ I2C 连续读 0x03~0x06（4 字节）
     │       ├─ 拼出 12 位 X/Y 坐标
     │       ├─ 叠加 TOUCH_OFFSET_X / TOUCH_OFFSET_Y
     │       └─ 喂给 LVGL indev
     │
     └─ LVGL 根据坐标 + 状态触发控件事件
```

## 面试清单

### Q1：I2C 和 SPI 有什么区别？

| 维度 | SPI | I2C |
|------|-----|-----|
| 线数 | 4（SCK/MOSI/MISO/CS） | 2（SCL/SDA） |
| 寻址 | 硬件 CS 引脚 | 软件 7-bit 地址码 |
| 总线设备数 | 加一个设备多一根 CS | 最多 127 个共用 2 线 |
| 速度 | MHz 级 | 100k/400kHz |
| 双工 | 全双工 | 半双工 |
| 流控 | 无 | ACK/NACK 应答 |
| 本项目用途 | LCD（SPI2） | 触摸+姿态+心率+温湿压+时钟（I2C1） |

### Q2：CST816S 7-bit 地址是什么？HAL 为什么传 8-bit？

7-bit 地址 = `0x15`。HAL 要求左移 1 位变成 `0x2A`（8-bit 写地址），因为 STM32 I2C 硬件寄存器期望地址左对齐到 bit7:1，bit0 由硬件根据收发方向自动填。你只需传同一个 8-bit 地址，HAL 根据你调用 `_Write` 还是 `_Read` 自动处理 R/W 位。

### Q3：触摸坐标怎么读出来的？

从寄存器 0x03~0x06 连续读 4 字节，X/Y 各占 12 位：
```
X = ((XposH[3:0] << 8) | XposL) + TOUCH_OFFSET_X
Y = ((YposH[3:0] << 8) | YposL) + TOUCH_OFFSET_Y
```
CST816S 支持地址自增，一次 `HAL_I2C_Mem_Read` 读完 4 字节。

### Q4：为什么不用 CST816S 硬件手势寄存器？

实测不可靠——单击和双击检测不稳定，不同芯片固件版本差异大。本项目只用 `GetFingerNum()` + `GetTouch()` 读原始状态，手势判断交给 LVGL 或应用层。

### Q5：触摸睡着后怎么唤醒？

I2C 发命令没用——芯片深度休眠后 I2C 接口已关闭。只能通过 RST 引脚硬件复位唤醒。
