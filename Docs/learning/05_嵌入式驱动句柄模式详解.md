# 嵌入式驱动高级设计：句柄模式与面向对象 C 编程

> 参考: LibDriver DS3231 驱动 (E:\XiYangWatch\Demo\RTC\driver_ds3231.c)  
> 目标: 写出可移植、可测试、可替换的 BSP 驱动  
> 适用: STM32 / nRF52 / ESP32 / GD32 / ... 任何平台

---

## 一、问题：传统驱动为什么不行

### 1.1 一个典型的传统驱动

```c
// ds3231.c — 传统写法
#include "i2c.h"   // ← 焊死了 STM32 的 HAL

uint8_t ds3231_read_time(uint8_t *h, uint8_t *m, uint8_t *s, ...)
{
    uint8_t buf[7];
    HAL_I2C_Mem_Read(&hi2c1, 0xD0, 0x00,          // ← 焊死了 HAL 函数
                     I2C_MEMADD_SIZE_8BIT, buf, 7, 100);
    *s = bcd_to_dec(buf[0]);                       // 这行是对的
    // ...
}
```

这段代码有两个"焊死"的地方：

| 焊死点 | 后果 |
|--------|------|
| `&hi2c1` | 只能用 I2C1。换到另一个 I2C 口要改驱动代码 |
| `HAL_I2C_Mem_Read()` | 只能跑在 STM32 上。换 nRF52 要重写整个文件 |
| 不检查返回值 | 芯片没回应 → 读了一堆 0xFF → 静默显示错误时间 |
| `100` 超时 | 硬编码，不同场景无法调整 |

**这种驱动叫"强耦合"——驱动代码和底层硬件焊死了。**

### 1.2 强耦合的代价

```
代价 1: 不可移植
  换 MCU → 全改。5 个传感器驱动，每个都要把 HAL 替换成新平台的 API。

代价 2: 不可测试
  想验证 BCD 解码对不对 → 必须烧到硬件上看。
  想在 PC 上跑测试 → 不可能，因为 HAL_I2C_Mem_Read 不存在于 PC 上。

代价 3: 不可复用
  两个项目都用 DS3231，但一个用硬件 I2C，一个用软件模拟 I2C（bit-bang）
  → 不得不维护两个版本的驱动。

代价 4: 静默失败
  不检查 HAL 返回值，I2C 通信失败时读到的全是垃圾数据，
  但程序照常跑，屏幕照常显示——直到用户发现时间是错的。
```

---

## 二、解决方案：句柄模式 (Handle Pattern)

### 2.1 核心思想

**"驱动不应该知道 HAL 的存在。驱动只需要知道：有人会在运行时告诉它怎么读 I2C。"**

```
传统:  驱动 ──直接调用──→ HAL_I2C_Mem_Read()  (编译期绑定)
         ↓
      换了 HAL → 驱动报废

句柄:  驱动 ──函数指针──→ ????  (运行时绑定)
         ↓
      ???? 可以是 HAL / TWI / Mock / 任何实现了接口的东西
```

### 2.2 用函数指针取代直接调用

```c
// 不写:
HAL_I2C_Mem_Read(&hi2c1, addr, reg, ..., buf, len, timeout);

// 写:
handle->iic_read(addr, reg, buf, len);
//
//  handle->iic_read 是一个函数指针。它指向谁，
//  是运行时由使用者决定的。驱动本身不知道也不关心。
```

### 2.3 句柄结构体

```c
typedef struct ds3231_handle_s {
    // ═══ 四个"虚函数" — 驱动依赖的能力 ═══
    uint8_t (*iic_read)(uint8_t addr, uint8_t reg, uint8_t *buf, uint16_t len);
    uint8_t (*iic_write)(uint8_t addr, uint8_t reg, uint8_t *buf, uint16_t len);
    void    (*delay_ms)(uint32_t ms);
    void    (*debug_print)(const char *fmt, ...);

    // ═══ 对象状态 — 驱动自己管理 ═══
    uint8_t inited;     // 0=未初始化, 1=已就绪
} ds3231_handle_t;
```

**这个结构体是全驱动的核心。** 它像一个插线板：

- 头 4 个成员 = 插孔（函数指针），指向谁由使用者决定
- `inited` = 电源指示灯，驱动内部管理，表示"插线板已经通电，可以用"

## 三、设计模式解析

这个驱动同时体现了 4 种经典设计模式：

### 3.1 桥接模式 (Bridge Pattern) — 主体

```
定义: "将抽象部分与实现部分分离，使它们都可以独立地变化。"

  抽象部分 = 驱动逻辑层 (ds3231.c)
    管: BCD 编解码、时间校验、闹钟逻辑、温度计算
    不管: I2C 时序、寄存器操作、延时实现

  实现部分 = 硬件操作层 (使用者提供)
    管: I2C 发送/接收、精确延时
    不管: 数据含义、业务逻辑

  桥接点 = 句柄结构体里的函数指针
    handle->iic_read(addr, reg, buf, len)

  桥接让他们两个独立变化:
    - 驱动变 (加新功能) → 硬件层不受影响
    - 硬件变 (换芯片)  → 驱动逻辑不受影响
```

```
        抽象面 (驱动)                  实现面 (硬件)
        ┌───────────┐                ┌──────────────┐
        │ DS3231     │                │ STM32 HAL    │
        │ 读时间      │    ┌─────┐    │ I2C1         │
        │ 设闹钟      │←──→│句柄 │←──→│              │
        │ 读温度      │    └─────┘    ├──────────────┤
        │ BCD 转换   │                │ nRF52 TWI    │
        └───────────┘                │ I2C0         │
                                     ├──────────────┤
                                     │ PC Mock      │
                                     │ 测试用假数据  │
                                     └──────────────┘
```

### 3.2 策略模式 (Strategy Pattern)

"驱动内部需要读写 I2C，但具体怎么读写，有不同的策略可以选。"

```c
// 策略 1: 硬件 I2C，有 DMA
handle->iic_read = stm32_i2c_dma_read;

// 策略 2: 硬件 I2C，无 DMA (轮询)
handle->iic_read = stm32_i2c_polling_read;

// 策略 3: 软件模拟 I2C (bit-bang，GPIO 翻转)
handle->iic_read = bitbang_i2c_read;

// 策略 4: PC 端模拟测试
handle->iic_read = mock_i2c_read;

// 驱动内部代码不变:
ds3231_get_time(&handle, &t);   // 内部自动用的是你注入的那个策略
```

### 3.3 依赖注入 (Dependency Injection)

"驱动不自己创建依赖，而是让使用者把依赖传进来。"

```c
// ❌ 传统: 驱动自己"new"依赖 — 写死了
void ds3231_init(void) {
    MX_I2C1_Init();     // 驱动自己调 HAL I2C 初始化
}

// ✅ 句柄模式: 依赖由外部注入 — 驱动只声明"我需要这些"
void ds3231_init(ds3231_handle_t *handle) {
    handle->iic_init();  // 这个函数是谁？我不知道，注入的人知道
}

// 使用者注入:
handle->iic_init = stm32_i2c1_init;   // 给你 STM32 版的实现
ds3231_init(&handle);                  // 驱动用注入的实现来初始化
```

**这就是面向对象语言里构造函数注入（Constructor Injection）的 C 语言等价物。**

### 3.4 模板方法模式 (Template Method)

"驱动定义算法的骨架（读时间 = 读寄存器 → BCD 解码 → 填结构体），其中'读寄存器'这一步延迟到运行时由注入的函数实现。"

```c
// 骨架 — 驱动定义的算法结构
uint8_t ds3231_get_time(ds3231_handle_t *handle, ds3231_time_t *t)
{
    uint8_t buf[7];

    // 第一步: 读硬件 — 具体怎么读由注入的函数决定 (模板方法)
    if (handle->iic_read(DS3231_ADDR, REG_SECOND, buf, 7) != 0) {
        return 1;
    }

    // 第二步: BCD 解码 — 这部分驱动自己管，不变
    t->second = bcd_to_dec(buf[0]);
    t->minute = bcd_to_dec(buf[1]);
    t->hour   = bcd_to_dec(buf[2] & 0x3F);
    t->date   = bcd_to_dec(buf[4]);
    t->month  = bcd_to_dec(buf[5] & 0x1F);
    t->year   = bcd_to_dec(buf[6]) + 2000;

    return 0;
}
```

第一步是"可变的"——注入不同实现就能换行为，第二步是"不变的"——BCD 解码逻辑永远一样。

## 四、完整的生命周期

### 4.1 五个阶段

```
① 分配句柄       ds3231_handle_t s_ds3231;
                 → 在栈上或静态区创建一个句柄

② 注入依赖       DRIVER_DS3231_LINK_IIC_READ(&s_ds3231, stm32_i2c_read);
                 → 把函数指针填入句柄

③ 初始化         ds3231_init(&s_ds3231);
                 → 调用注入的 iic_init()，验证芯片存在，设 inited=1

④ 正常使用       ds3231_get_time(&s_ds3231, &t);
                 → 每个 API 内部检查 inited==1 才执行

⑤ 销毁           ds3231_deinit(&s_ds3231);
                 → 调用注入的 iic_deinit()，设 inited=0
```

### 4.2 inited 标志的防御作用

```c
// 每个对外 API 的前三行 — 防御三板斧:
uint8_t ds3231_get_time(ds3231_handle_t *handle, ds3231_time_t *t)
{
    if (handle == NULL)        return 2;   // 斧1: 句柄空 — 使用者忘分配
    if (handle->inited != 1)   return 3;   // 斧2: 未初始化 — 使用者忘调 init
    if (t == NULL)             return 2;   // 斧3: 输出空 — 使用者忘传指针

    // 现在可以安全干活了
    // ...
}

// 没有这三行的后果:
//   如果 handle 是 NULL → handle->iic_read() → CPU 跳转到地址 0
//   → HardFault → 死机 → 你花 3 小时排查
// 有了这三行:
//   → 返回错误码 3 → 你在调用处收到错误 → 立刻知道忘了调 init
```

## 五、错误处理体系

### 5.1 返回值约定

| 返回值 | 含义 | 例子 |
|:------:|------|------|
| **0** | 成功 | 读写正常完成 |
| **1** | 硬件失败 | I2C 超时、NACK、芯片无响应 |
| **2** | 参数非法 | handle 或输入指针为 NULL |
| **3** | 状态非法 | 没调 init 就调了 API |
| **4** | 数据非法 | 校验失败、时间值越界 |

### 5.2 错误不吞、逐层上报

```c
// 底层: I2C 读，出错立即 return
static uint8_t i2c_read_reg(ds3231_handle_t *h, uint8_t reg, uint8_t *buf, uint8_t len)
{
    if (h->iic_read(DS3231_ADDR, reg, buf, len) != 0) {
        h->debug_print("ds3231: i2c read reg 0x%02X failed\n", reg);
        return 1;    // ← 立刻上报，不吞错误
    }
    return 0;
}

// 中层: 读时间，底层出错 → 中层也报错
uint8_t ds3231_get_time(ds3231_handle_t *h, ds3231_time_t *t)
{
    if (i2c_read_reg(h, REG_SECOND, buf, 7) != 0) {
        return 1;    // ← 上报给更上层
    }
    // ...
}

// 上层 (I2CSensTask): 收到了错误，决定怎么办
if (ds3231_get_time(&s_ds3231, &t) != 0) {
    log_printf("[ERR] RTC read failed\n");
    g_shm.sens_health.rtc = SENS_FAILED;  // 标记传感器故障
    return;  // 跳过这轮，下次再试
}
```

**反例（不要这么写）:**

```c
h->iic_read(...);  // 不管返回值，当它一定成功
// 如果芯片没回 → buf 里全是 0xFF → BCD 解码出 255:255:255
// → 屏幕显示 "FF:FF:FF" → 用户以为手表坏了
```

## 六、完整示例：从零使用 DS3231 句柄驱动

### 6.1 写注入函数（适配层）

```c
/* ═══ 适配层: 把 STM32 HAL 包装成驱动要的签名 ═══ */

#include "i2c.h"   // 提供 hi2c1

// HAL 原型:
//   HAL_I2C_Mem_Read(I2C_HandleTypeDef*, uint16_t DevAddr,
//                    uint16_t MemAddr, uint16_t MemAddSize,
//                    uint8_t*, uint16_t Size, uint32_t Timeout)
// 驱动要求的原型:
//   uint8_t (*iic_read)(uint8_t addr, uint8_t reg, uint8_t *buf, uint16_t len)

static uint8_t stm32_i2c1_read(uint8_t addr, uint8_t reg, uint8_t *buf, uint16_t len)
{
    HAL_StatusTypeDef rc;
    rc = HAL_I2C_Mem_Read(&hi2c1, (uint16_t)addr, (uint16_t)reg,
                          I2C_MEMADD_SIZE_8BIT, buf, (uint16_t)len, 100);
    return (rc == HAL_OK) ? 0 : 1;
}

static uint8_t stm32_i2c1_write(uint8_t addr, uint8_t reg, uint8_t *buf, uint16_t len)
{
    HAL_StatusTypeDef rc;
    rc = HAL_I2C_Mem_Write(&hi2c1, (uint16_t)addr, (uint16_t)reg,
                           I2C_MEMADD_SIZE_8BIT, buf, (uint16_t)len, 100);
    return (rc == HAL_OK) ? 0 : 1;
}

static uint8_t stm32_i2c1_init(void)
{
    // I2C1 已在 CubeMX 生成的 MX_I2C1_Init() 中初始化
    // 这里只需验证总线状态
    return (HAL_I2C_GetState(&hi2c1) == HAL_I2C_STATE_READY) ? 0 : 1;
}

static void stm32_delay(uint32_t ms)
{
    osDelay(ms);   // FreeRTOS 版
}
```

### 6.2 创建 + 注入 + 使用

```c
/* ═══ 在 I2CSensTask 中 ═══ */

#include "ds3231.h"

static ds3231_handle_t s_rtc;    // ① 创建句柄 (静态变量, 只在本文件可见)

void I2CSensTask(void *pvParameters)
{
    // ② 注入依赖 — 告诉驱动 "用这些函数操作硬件"
    DRIVER_DS3231_LINK_INIT(&s_rtc, ds3231_handle_t);
    DRIVER_DS3231_LINK_IIC_INIT(&s_rtc, stm32_i2c1_init);
    DRIVER_DS3231_LINK_IIC_READ(&s_rtc, stm32_i2c1_read);
    DRIVER_DS3231_LINK_IIC_WRITE(&s_rtc, stm32_i2c1_write);
    DRIVER_DS3231_LINK_DELAY_MS(&s_rtc, stm32_delay);
    DRIVER_DS3231_LINK_DEBUG_PRINT(&s_rtc, log_printf);
    DRIVER_DS3231_LINK_RECEIVE_CALLBACK(&s_rtc, NULL);  // 不用中断

    // ③ 初始化
    if (ds3231_init(&s_rtc) != 0) {
        log_printf("[ERR] DS3231 init failed\n");
    }

    // ④ 主循环中使用
    for (;;) {
        if (counter % 200 == 0) {
            ds3231_time_t t;
            if (ds3231_get_time(&s_rtc, &t) == 0) {
                g_shm.time.hour    = t.hour;
                g_shm.time.min     = t.minute;
                g_shm.time.sec     = t.second;
                g_shm.time.day     = t.date;
                g_shm.time.month   = t.month;
                g_shm.time.weekday = t.week;
                g_shm.time.year    = t.year;
            }
        }
        // ...
    }

    // ⑤ 销毁 (通常只在系统关机时调用)
    // ds3231_deinit(&s_rtc);
}
```

## 七、对比传统驱动 vs 句柄驱动

| 维度 | 传统驱动 (宏+HAL) | 句柄驱动 |
|------|-------------------|---------|
| **硬件绑定** | 编译期确定，焊死 | 运行时注入，可替换 |
| **跨平台** | 每换 MCU 重写驱动 | 驱动代码 0 改动，只重写注入函数 |
| **单元测试** | 不可能，必须接硬件 | 注入 mock 函数，PC 上随便测 |
| **多实例** | 不支持（宏只能指一个 I2C） | 支持（创建第二个句柄，注入第二个 I2C） |
| **错误处理** | 通常忽略返回值 | 每层检查，逐层上报 |
| **代码量** | 少（100 行） | 多（注入+检查约增加 50% 代码量） |
| **学习曲线** | 低 | 中（要理解函数指针和句柄） |

## 八、为什么这么设计 — 核心思想溯源

### 8.1 依赖倒置原则 (Dependency Inversion Principle)

SOLID 原则中的 "D"：

```
定义: "高层模块不应该依赖低层模块，二者都应该依赖抽象。"

  高层模块 = 驱动 (DS3231 逻辑)
  低层模块 = HAL (STM32 寄存器操作)
  抽象 = 函数指针接口 (iic_read / iic_write)

  传统: 驱动 → HAL      (高层依赖低层 ❌)
  句柄: 驱动 → 抽象 ← HAL  (都依赖抽象 ✅)
```

### 8.2 开闭原则 (Open-Closed Principle)

SOLID 原则中的 "O"：

```
定义: "对扩展开放，对修改关闭。"

  想支持一种新的 I2C 实现?
    传统: 改驱动代码 → 可能引入 bug
    句柄: 写一个新的注入函数 → 驱动代码不动

  想加单元测试?
    传统: 整个架构不支持
    句柄: 注入一个 mock 函数 → 驱动代码不动
```

### 8.3 好莱坞原则 (Hollywood Principle)

```
"Don't call us, we'll call you." (不要调我们，我们会调你)

  传统: 驱动主动调 HAL  →  "我去找 HAL 干活"
  句柄: 驱动被注入函数  →  "你给我函数，需要时我会调"
        → HAL 不再被驱动依赖 → HAL 变成驱动的一个"插件"
```

## 九、和面向对象的对照

C 语言做面向对象靠三样工具，这个驱动全用了：

| OOP 概念 | C 语言实现 | 本驱动中的体现 |
|----------|-----------|--------------|
| **类** | 结构体 | `ds3231_handle_t` |
| **成员变量** | 结构体的数据成员 | `inited` |
| **虚函数** | 函数指针成员 | `iic_read`, `iic_write` |
| **this 指针** | 第一个参数传句柄 | `ds3231_get_time(handle, ...)` |
| **接口** | 函数指针的集合 | 4 个 `(*)(...)` 成员 |
| **构造函数** | `xxx_init(handle)` | `ds3231_init()` 检查依赖 + 设置 `inited=1` |
| **析构函数** | `xxx_deinit(handle)` | `ds3231_deinit()` 释放资源 + 设置 `inited=0` |
| **依赖注入** | `LINK_XXX(HANDLE, FUC)` 宏 | `DRIVER_DS3231_LINK_IIC_READ()` |
| **封装** | 内部函数 `static` + 句柄不透明 | `a_ds3231_iic_read()` 是 `static` 的 |

如果用 C++ 改写同一个驱动，结构完全一样，只是语法糖不同：

```c++
class DS3231 {
    // 接口 — 需要使用者实现
    virtual uint8_t iic_read(uint8_t addr, uint8_t reg, uint8_t *buf, uint16_t len) = 0;
    virtual uint8_t iic_write(...) = 0;
    virtual void delay_ms(uint32_t ms) = 0;

    bool m_inited = false;

public:
    uint8_t init();          // 内部调 iic_read/write
    uint8_t get_time(time_t *t);
    uint8_t set_time(time_t *t);
};

// 使用者继承并实现接口:
class STM32_DS3231 : public DS3231 {
    uint8_t iic_read(...) override { return HAL_I2C_Mem_Read(...); }
    uint8_t iic_write(...) override { return HAL_I2C_Mem_Write(...); }
};
```

C 的句柄模式和 C++ 的纯虚基类本质上是一个东西——都定义了"什么能力"，但不定义"怎么实现"。

## 十、落地路线

我们的 XiYangWatch 项目中已有 2 个 BSP 驱动，还要建 3 个。路线：

```
① 设计一个轻量版的"句柄模板" — 比 LibDriver 简单，4 个函数指针 + inited
② 按模板重写 DS3231 驱动
③ 按模板写 BME280 / QMI8658 / MAX30102 驱动
④ 在 I2CSensTask 中统一注入，5 个传感器同一个套路
⑤ CST816 保持现有宏方案 (它是单实例、无需移植)
```

## 十一、面试要点速记

如果面试被问到"你怎么设计可移植的嵌入式驱动"：

```
1. 桥接模式: 驱动逻辑(抽象) 和 硬件操作(实现) 通过函数指针解耦
2. 句柄结构体: 存放函数指针 + 对象状态，传参相当于 this
3. 依赖注入: 使用者在 init 前把 HAL 函数填入句柄
4. 防御编程: 每个 API 检查 handle!=NULL && inited==1
5. 错误体系: 返回值统一含义 (0=OK, 1=硬件, 2=参数, 3=状态, 4=数据)
6. 好处: 同一份驱动代码可换 STM32/nRF/GD32，可 mock 测试
```
