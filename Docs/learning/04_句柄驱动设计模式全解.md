## 一、传统驱动为什么不行

### 1.1 典型的传统驱动

```c
// ds3231.c — 传统写法
#include "i2c.h"   // ← 焊死了 STM32 的 HAL

uint8_t ds3231_read_time(uint8_t *h, uint8_t *m, uint8_t *s, ...)
{
    uint8_t buf[7];
    HAL_I2C_Mem_Read(&hi2c1, 0xD0, 0x00,          // ← 焊死了 HAL 函数
                     I2C_MEMADD_SIZE_8BIT, buf, 7, 100);
    *s = bcd_to_dec(buf[0]);
}
```

两个"焊死"点：

| 焊死点 | 后果 |
|--------|------|
| `&hi2c1` | 只能用 I2C1。换到另一个 I2C 口要改驱动代码 |
| `HAL_I2C_Mem_Read()` | 只能跑在 STM32 上。换 nRF52 要重写整个文件 |
| 不检查返回值 | 芯片没回应 → 读了一堆 0xFF → 静默显示错误时间 |
| `100` 超时 | 硬编码，不同场景无法调整 |

### 1.2 强耦合的代价

```
代价 1: 不可移植 — 换 MCU 全改
代价 2: 不可测试 — 必须在硬件上验证，PC 上跑不了
代价 3: 不可复用 — 硬件 I2C vs 软件模拟 I2C，两个版本
代价 4: 静默失败 — 不检查 HAL 返回值，出错了不知道
```

## 三、核心机制：句柄模式

### 3.1 思想

**"驱动不应该知道 HAL 的存在。驱动只需要声明它需要什么能力，让使用者告诉它这些能力由谁提供。"**

```
传统:  驱动 ──直接调用──→ HAL_I2C_Mem_Read()  (编译期绑定)
         ↓
      换了 HAL → 驱动报废

句柄:  驱动 ──函数指针──→ ????  (运行时绑定)
         ↓
      ???? 可以是 HAL / TWI / Mock / 任何实现了接口的东西
```

### 3.2 句柄结构体

```c
typedef struct ds3231_handle_s {
    // ═══ 7 个虚函数 — 驱动依赖的能力 ═══
    uint8_t (*iic_init)(void);
    uint8_t (*iic_deinit)(void);
    uint8_t (*iic_read)(uint8_t addr, uint8_t reg, uint8_t *buf, uint16_t len);
    uint8_t (*iic_write)(uint8_t addr, uint8_t reg, uint8_t *buf, uint16_t len);
    void    (*delay_ms)(uint32_t ms);
    void    (*debug_print)(const char *fmt, ...);
    void    (*receive_callback)(uint8_t type);

    // ═══ 1 个状态变量 — 驱动自己管理 ═══
    uint8_t inited;
} ds3231_handle_t;
```

这个结构体像一个插线板——函数指针是插孔，`inited` 是电源指示灯。

### 3.3 Link 宏 — 依赖注入的语法糖

```c
#define DRIVER_DS3231_LINK_INIT(HANDLE, STRUCTURE)   memset(HANDLE, 0, sizeof(STRUCTURE))
#define DRIVER_DS3231_LINK_IIC_INIT(HANDLE, FUC)     (HANDLE)->iic_init = FUC
#define DRIVER_DS3231_LINK_IIC_READ(HANDLE, FUC)     (HANDLE)->iic_read = FUC
#define DRIVER_DS3231_LINK_IIC_WRITE(HANDLE, FUC)    (HANDLE)->iic_write = FUC
#define DRIVER_DS3231_LINK_DELAY_MS(HANDLE, FUC)     (HANDLE)->delay_ms = FUC
#define DRIVER_DS3231_LINK_DEBUG_PRINT(HANDLE, FUC)  (HANDLE)->debug_print = FUC
#define DRIVER_DS3231_LINK_RECEIVE_CALLBACK(HANDLE, FUC) (HANDLE)->receive_callback = FUC
```

## 四、各层代码剖析

### 4.1 src/ — 核心驱动层（主角）

不使用任何 HAL 函数。所有硬件操作通过 `handle->xxx()` 函数指针进行。

```c
// src/driver_ds3231.c — 读时间
uint8_t ds3231_get_time(ds3231_handle_t *handle, ds3231_time_t *t)
{
    uint8_t buf[7];

    // ① 防御三板斧
    if (handle == NULL)       return 2;
    if (handle->inited != 1)  return 3;
    if (t == NULL)            return 2;

    // ② 通过函数指针读 I2C (不知道谁提供的)
    if (a_ds3231_iic_multiple_read(handle, 0x00, buf, 7) != 0) {
        handle->debug_print("ds3231: multiple read failed.\n");
        return 1;
    }

    // ③ BCD 解码 — 纯逻辑, 和平台无关
    t->second = bcd2hex(buf[0]);
    t->minute = bcd2hex(buf[1]);
    t->hour   = bcd2hex(buf[2] & 0x3F);         // 屏蔽 12/24h 位
    t->week   = bcd2hex(buf[3]);
    t->date   = bcd2hex(buf[4]);
    t->month  = bcd2hex(buf[5] & 0x1F);         // 屏蔽 century 位
    t->year   = bcd2hex(buf[6]) + 2000
              + ((buf[5] >> 7) & 0x01) * 100;   // 世纪位: 支持 2100+

    return 0;
}
```

**看点**：
- 世纪位不仅读出，还正确计算年份（支持 1900~2299）
- `buf[2] & 0x3F` 和 `buf[5] & 0x1F` 是防御性屏蔽
- 内部函数 `a_ds3231_iic_multiple_read` 是 `static` 的，封装了多字节读逻辑

### 4.2 interface/ — 平台适配层（使用者实现）

不存在于 ds3231 源码中——是一组**必须由使用者提供的函数模板**。驱动本身不和任何平台绑定。

```
使用者需要实现 7 个函数:
  ① ds3231_interface_iic_init(void)           → 初始化 I2C 总线
  ② ds3231_interface_iic_deinit(void)         → 反初始化 I2C
  ③ ds3231_interface_iic_read(addr,reg,buf,len)  → 从 I2C 读
  ④ ds3231_interface_iic_write(addr,reg,buf,len) → 向 I2C 写
  ⑤ ds3231_interface_delay_ms(ms)             → 毫秒延时
  ⑥ ds3231_interface_debug_print(fmt, ...)    → 调试日志
  ⑦ ds3231_interface_receive_callback(type)   → 中断回调
```

**适配器示例** — 把 HAL 签名翻译成驱动要求的签名：

```c
// HAL 原型:
//   HAL_I2C_Mem_Read(I2C_HandleTypeDef*, uint16_t DevAddr,
//     uint16_t MemAddr, uint16_t MemAddSize, uint8_t*, uint16_t, uint32_t)

// 驱动要求的原型:
//   uint8_t (*iic_read)(uint8_t addr, uint8_t reg, uint8_t *buf, uint16_t len)

static uint8_t platform_i2c_read(uint8_t addr, uint8_t reg,
                                  uint8_t *buf, uint16_t len)
{
    HAL_StatusTypeDef rc;
    rc = HAL_I2C_Mem_Read(&hi2c1, (uint16_t)addr, (uint16_t)reg,
                          I2C_MEMADD_SIZE_8BIT, buf, (uint16_t)len, 100);
    return (rc == HAL_OK) ? 0 : 1;    // HAL_OK→0, 其他→1
}
```

### 4.4 test/ — 测试框架层

测试和产品代码用同一套 Link 宏 + 注入机制——测试时注入真的 I2C 函数（接硬件），也可以注入假的 I2C 函数（返回预设值）。

```c
uint8_t ds3231_readwrite_test(uint32_t times)

    for (i = 0; i < times; i++) {
        ds3231_set_time(&gs_handle, &time_in);
        ds3231_get_time(&gs_handle, &time_out);
        // 验证 time_in == time_out
    }
}
```

## 五、涉及的设计模式

这个驱动同时体现了 5 种经典设计模式：

### 5.1 桥接模式 (Bridge) — 主体结构

```
定义: "将抽象部分与实现部分分离，使它们都可以独立地变化。"

  抽象部分 = src/driver_ds3231.c (BCD 编解码、时间校验、闹钟逻辑)
  实现部分 = 使用者写的 7 个函数 (I2C 读写、延时、日志)
  桥接点   = 句柄结构体里的函数指针 handle->iic_read(...)

  桥接让它们独立变化:
    - 驱动加新功能 → 硬件层不受影响
    - 换 MCU       → 驱动逻辑不受影响
```

```
        抽象面 (驱动)                  实现面 (硬件)
        ┌───────────┐                ┌──────────────┐
        │ DS3231     │                │ STM32 HAL    │
        │ 读/写时间  │    ┌─────┐    │ I2C1         │
        │ 设闹钟     │←──→│句柄 │←──→│ nRF52 TWI    │
        │ 读温度     │    └─────┘    │ 软件模拟 I2C │
        │ BCD 转换   │                │ PC Mock      │
        └───────────┘                └──────────────┘
```

### 5.2 依赖注入 (Dependency Injection)

驱动不创建依赖——它声明"我需要哪些能力"，由使用者注入。

```c
// ❌ 传统: 驱动自己创建依赖
void ds3231_init(void) {
    MX_I2C1_Init();     // 驱动自己调 HAL
}

// ✅ 句柄: 依赖由外部注入
void ds3231_init(ds3231_handle_t *handle) {
    handle->iic_init();  // 这个函数是谁？使用者注入的
}

// 使用者注入:
handle->iic_init = stm32_i2c1_init;
ds3231_init(&handle);
```

### 5.3 模板方法 (Template Method)

驱动定义算法骨架，"读硬件"这一步由注入的函数实现。

```c
uint8_t ds3231_get_time(ds3231_handle_t *handle, ds3231_time_t *t)
{
    read_registers(buf);    // ← 模板方法：具体怎么读，由注入者决定
    bcd_decode(buf, t);     // ← 固定步骤：BCD 解码逻辑永不变
    validate_time(t);       // ← 固定步骤
}
```

### 5.4 策略模式 (Strategy)

同一个 I2C 读操作，可以选择不同策略。

```c
handle->iic_read = stm32_i2c_dma_read;     // 策略 A: 硬件 DMA
handle->iic_read = stm32_i2c_polling_read; // 策略 B: 硬件轮询
handle->iic_read = bitbang_i2c_read;       // 策略 C: GPIO 模拟
handle->iic_read = mock_i2c_read;          // 策略 D: 假数据
// 驱动内部代码不变 — 多态!
ds3231_get_time(&handle, &t);
```

### 5.5 适配器模式 (Adapter)

HAL 的函数签名和驱动要求的不一致，用适配函数转换。

```c
// 驱动要求: uint8_t (*iic_read)(uint8_t addr, uint8_t reg, uint8_t *buf, uint16_t len)
// HAL 提供:  HAL_StatusTypeDef HAL_I2C_Mem_Read(..., uint16_t DevAddr, ...)

// 适配器 — 签名翻译:
static uint8_t platform_i2c_read(uint8_t addr, uint8_t reg, uint8_t *buf, uint16_t len)
{
    return (HAL_I2C_Mem_Read(&hi2c1, addr, reg, I2C_MEMADD_SIZE_8BIT, buf, len, 100) == HAL_OK) ? 0 : 1;
}
```

## 六、完整使用流程

### 6.1 第一步：写平台适配函数

```c
static uint8_t my_i2c_init(void) {
    return (HAL_I2C_GetState(&hi2c1) == HAL_I2C_STATE_READY) ? 0 : 1;
}
static uint8_t my_i2c_read(uint8_t addr, uint8_t reg, uint8_t *buf, uint16_t len) {
    return (HAL_I2C_Mem_Read(&hi2c1, addr, reg, I2C_MEMADD_SIZE_8BIT, buf, len, 100) == HAL_OK) ? 0 : 1;
}
static uint8_t my_i2c_write(uint8_t addr, uint8_t reg, uint8_t *buf, uint16_t len) {
    return (HAL_I2C_Mem_Write(&hi2c1, addr, reg, I2C_MEMADD_SIZE_8BIT, buf, len, 100) == HAL_OK) ? 0 : 1;
}
static void my_delay(uint32_t ms) { osDelay(ms); }
static void my_log(const char *fmt, ...) {
    va_list args; va_start(args, fmt);
    SEGGER_RTT_vprintf(0, fmt, &args);
    va_end(args);
}
```

### 6.2 第二步：注入 + 初始化 + 使用

```c
#include "driver_ds3231.h"
static ds3231_handle_t s_rtc;     // ① 创建句柄

void I2CSensTask(void *pvParameters)
{
    // ② 注入依赖 — 7 行 Link 宏
    DRIVER_DS3231_LINK_INIT(&s_rtc, ds3231_handle_t);
    DRIVER_DS3231_LINK_IIC_INIT(&s_rtc, my_i2c_init);
    DRIVER_DS3231_LINK_IIC_READ(&s_rtc, my_i2c_read);
    DRIVER_DS3231_LINK_IIC_WRITE(&s_rtc, my_i2c_write);
    DRIVER_DS3231_LINK_DELAY_MS(&s_rtc, my_delay);
    DRIVER_DS3231_LINK_DEBUG_PRINT(&s_rtc, my_log);
    DRIVER_DS3231_LINK_RECEIVE_CALLBACK(&s_rtc, NULL);

    // ③ 初始化 + 配置
    ds3231_init(&s_rtc);
    ds3231_set_oscillator(&s_rtc, DS3231_BOOL_TRUE);
    ds3231_set_alarm_interrupt(&s_rtc, DS3231_ALARM_1, DS3231_BOOL_FALSE);
    ds3231_set_square_wave(&s_rtc, DS3231_BOOL_FALSE);
    ds3231_set_32khz_output(&s_rtc, DS3231_BOOL_FALSE);

    // ④ 主循环使用
    for (;;) {
        if (counter % 200 == 0) {
            ds3231_time_t t;
            if (ds3231_get_time(&s_rtc, &t) == 0) {
                g_shm.time.hour    = t.hour;
                g_shm.time.min     = t.minute;
                g_shm.time.sec     = t.second;
                g_shm.time.weekday = t.week;
                // ...
            }
        }
    }
    // ⑤ 销毁
    ds3231_deinit(&s_rtc);
}
```

## 七、生命周期管理

```
① 分配句柄       ds3231_handle_t s_ds3231;
② 注入依赖       7 个 Link 宏把函数指针填入句柄
③ 初始化         ds3231_init() → 调 iic_init() → 验证芯片 → inited=1
④ 正常使用       ds3231_get_time() → 检查 inited==1 → 执行
⑤ 销毁           ds3231_deinit() → 调 iic_deinit() → inited=0
```

### inited 标志的防御作用

```c
// 每个对外 API 的前三行 — 防御三板斧:
uint8_t ds3231_get_time(ds3231_handle_t *handle, ds3231_time_t *t)
{
    if (handle == NULL)        return 2;   // 斧1: 句柄空
    if (handle->inited != 1)   return 3;   // 斧2: 未初始化
    if (t == NULL)             return 2;   // 斧3: 输出空
    // 现在可以安全干活了
}

// 没有这三行的后果:
//   handle=NULL → handle->iic_read() → 跳转到地址 0 → HardFault → 死机
```

## 八、错误处理体系

### 8.1 返回值约定

| 返回值 | 含义 | 典型原因 |
|:------:|------|---------|
| **0** | 成功 | 操作正常 |
| **1** | 硬件失败 | I2C NACK、超时、芯片无响应 |
| **2** | 参数非法 | handle 或输入指针为 NULL |
| **3** | 状态非法 | 没调 init 就调了 API |
| **4** | 数据非法 | 时间字段越界 |

### 8.2 错误不吞、逐层上报

```c
// 底层 — 报错
if (handle->iic_read(addr, reg, buf, len) != 0) {
    handle->debug_print("i2c read failed\n");
    return 1;                       // ← 立刻上报
}

// 中层 — 透传
res = i2c_read_reg(handle, ...);
if (res != 0) return 1;

// 顶层 — 决策
if (ds3231_get_time(&s_rtc, &t) != 0) {
    g_shm.sens_health.rtc = SENS_RETRYING;   // 标记异常
    return;                                   // 跳过这轮，下次重试
}
```

**反例（不要这么写）**：

```c
h->iic_read(...);  // 不管返回值
// 芯片没回 → buf 全是 0xFF → BCD 解码出 255:255:255 → 屏幕显示 "FF:FF:FF"
```

## 九、10 项防御性编程措施

1. 每个 API 入口验证 `handle != NULL`
2. 每个 API 入口验证 `inited == 1`
3. 每个输出参数验证 `!= NULL`
4. `init()` 验证所有函数指针已注入
5. `init()` 失败时调 `deinit()` 清理
6. 硬件操作后立即检查返回值
7. 时间值写入前校验范围（12h 模式不允许 hour=0 或 >12）
8. `memset` 清零局部缓冲区
9. 世纪位独立处理（不硬编码 `year + 2000`，支持 1900~2299）
10. 12h/24h 模式自适应（读 format 位，按实际模式解码）

## 十、可测试性

驱动可以在 PC 上做单元测试：

```c
// Mock: 返回预设数据，不接硬件
static uint8_t mock_i2c_read(uint8_t addr, uint8_t reg, uint8_t *buf, uint16_t len)
{
    uint8_t fake[] = {0x00, 0x30, 0x14, 0x06, 0x05, 0x06, 0x26};
    memcpy(buf, fake, len);
    return 0;
}

void test_bcd_decode_on_pc()
{
    ds3231_handle_t handle;
    DRIVER_DS3231_LINK_IIC_READ(&handle, mock_i2c_read);
    handle.inited = 1;

    ds3231_time_t t;
    ds3231_get_time(&handle, &t);
    assert(t.year == 2026);      // 世纪位: 26+2000=2026
    assert(t.month == 6);
    assert(t.hour == 20);        // 24h 模式, 0x14=20
}
```

**没有句柄模式之前，这段测试不可能跑在 PC 上。**

## 十一、对比表

| 维度 | 传统驱动 (宏+HAL) | 句柄驱动 |
|------|:--:|:--:|
| **硬件绑定** | 编译期焊死 | 运行时注入，可替换 |
| **跨平台** | 换 MCU 重写 | 驱动 0 改动，只重写适配函数 |
| **单元测试** | 不可能 | 注入 mock，PC 上随便测 |
| **多实例** | 不支持 | 创建第二个句柄，注入第二个 I2C |
| **错误处理** | 通常忽略 | 每层检查，逐层上报 |
| **代码量** | 100 行 | 增加 ~50%（注入+检查） |
| **学习曲线** | 低 | 中 |

## 十二、设计原则溯源

### 依赖倒置原则 (DIP — SOLID 中的 D)

```
"高层模块不应该依赖低层模块，二者都应该依赖抽象。"

  高层模块 = 驱动 (DS3231 逻辑)
  低层模块 = HAL (STM32 寄存器操作)
  抽象     = 函数指针接口 (iic_read / iic_write)

  传统: 驱动 → HAL           (高层依赖低层 ❌)
  句柄: 驱动 → 抽象 ← HAL    (都依赖抽象 ✅)
```

### 开闭原则 (OCP — SOLID 中的 O)

```
"对扩展开放，对修改关闭。"

  想支持新的 I2C 实现?
    传统: 改驱动代码 → 可能引入 bug
    句柄: 写新的注入函数 → 驱动代码不动
```

### 好莱坞原则

```
"Don't call us, we'll call you."

  传统: 驱动主动调 HAL  →  "我去找 HAL 干活"
  句柄: HAL 被注入驱动  →  "你给我函数，需要时我会调"
```

## 十三、C 语言的"面向对象"

C 做面向对象靠三样工具，这个驱动全用了：

| OOP 概念 | C 语言实现 | 驱动中的体现 |
|----------|-----------|--------------|
| **类** | 结构体 | `ds3231_handle_t` |
| **成员变量** | 结构体数据成员 | `inited` |
| **虚函数** | 函数指针成员 | `iic_read`, `iic_write` |
| **this 指针** | 第一个参数传句柄 | `ds3231_get_time(handle, ...)` |
| **接口** | 函数指针集合 | 7 个 `(*)(...)` 成员 |
| **构造函数** | `xxx_init(handle)` | `ds3231_init()` |
| **析构函数** | `xxx_deinit(handle)` | `ds3231_deinit()` |
| **依赖注入** | `LINK_XXX(HANDLE, FUC)` | `DRIVER_DS3231_LINK_IIC_READ()` |
| **封装** | 内部函数 `static` | `a_ds3231_iic_read()` 是 `static` |

如果用 C++ 改写，结构完全一样：

```c++
class DS3231 {
    virtual uint8_t iic_read(uint8_t addr, uint8_t reg, uint8_t *buf, uint16_t len) = 0;
    virtual uint8_t iic_write(...) = 0;
    virtual void delay_ms(uint32_t ms) = 0;
    bool m_inited = false;
public:
    uint8_t init();
    uint8_t get_time(time_t *t);
};
```

## 十五、面试要点速记

```
Q: "你怎么设计可移植的嵌入式驱动？"

A:
  1. 桥接模式: 驱动逻辑(抽象) 和 硬件操作(实现) 通过函数指针解耦
  2. 句柄结构体: 存函数指针 + 对象状态，传参第一参相当于 this
  3. 依赖注入: 使用者在 init 前把平台函数通过 Link 宏填入句柄
  4. 防御编程: 每个 API 检查 handle!=NULL && inited==1 再执行
  5. 错误体系: 返回值 0=OK/1=HW/2=Param/3=State/4=Data
  6. 好处: 同份代码换 MCU 不改，可在 PC mock 测试
```

## 十六、核心理念

```
"好的嵌入式驱动不调用 HAL。
 它声明自己需要什么能力，
 让使用者告诉它这些能力由谁提供。"
```

这就是这个完整开源项目 1700+ 行代码背后的全部设计思想。
