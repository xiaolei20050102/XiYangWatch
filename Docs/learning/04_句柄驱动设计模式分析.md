## 一、核心设计：句柄模式 (Handle Pattern)

### 1.1 什么是句柄模式

不直接调用 HAL，而是通过一个"句柄"结构体里的函数指针来操作硬件。句柄 = 对象的 this 指针。

```
传统嵌入式驱动:              句柄模式驱动:
  ds3231.c                    ds3231.c (纯逻辑)
    ↓ 直接调                    ↓ 调函数指针
  HAL_I2C_Mem_Read()          handle->iic_read()
    ↓                            ↓
  STM32 寄存器               运行时注入的实现 (HAL / nRF / Mock)
```

### 1.2 句柄结构体

```c
typedef struct ds3231_handle_s {
    // ═══ 依赖注入 (由使用者在初始化前填入) ═══
    uint8_t (*iic_init)(void);                                      // I2C 初始化
    uint8_t (*iic_deinit)(void);                                    // I2C 反初始化
    uint8_t (*iic_read)(uint8_t addr, uint8_t reg, uint8_t *buf, uint16_t len);   // I2C 读
    uint8_t (*iic_write)(uint8_t addr, uint8_t reg, uint8_t *buf, uint16_t len);  // I2C 写
    void    (*delay_ms)(uint32_t ms);                               // 毫秒延时
    void    (*debug_print)(const char *const fmt, ...);             // 调试输出
    void    (*receive_callback)(uint8_t type);                      // 中断回调

    // ═══ 对象状态 (由驱动内部管理) ═══
    uint8_t inited;                                                 // 是否已初始化
} ds3231_handle_t;
```

**关键**：这个结构体里没有一行 HAL 代码。无论换什么 MCU，驱动本身的 .c 文件一字不改。

### 1.3 依赖注入 — Link 宏

```c
// 使用者在 main.c 或 i2c_sens_task.c 里:
static ds3231_handle_t g_ds3231;                                    // ① 创建句柄

DRIVER_DS3231_LINK_INIT(&g_ds3231, ds3231_handle_t);               // ② 清零句柄
DRIVER_DS3231_LINK_IIC_INIT(&g_ds3231, stm32_i2c_init);            // ③ 注入 I2C 初始化函数
DRIVER_DS3231_LINK_IIC_READ(&g_ds3231, stm32_i2c_read);            // ④ 注入 I2C 读函数
DRIVER_DS3231_LINK_IIC_WRITE(&g_ds3231, stm32_i2c_write);          // ⑤ 注入 I2C 写函数
DRIVER_DS3231_LINK_DELAY_MS(&g_ds3231, HAL_Delay);                 // ⑥ 注入延时函数
DRIVER_DS3231_LINK_DEBUG_PRINT(&g_ds3231, log_printf);             // ⑦ 注入日志函数
DRIVER_DS3231_LINK_RECEIVE_CALLBACK(&g_ds3231, ds3231_callback);   // ⑧ 注入中断回调

ds3231_init(&g_ds3231);                                            // ⑨ 初始化
```

Link 宏内部就是函数指针赋值：
```c
#define DRIVER_DS3231_LINK_IIC_READ(HANDLE, FUC)  (HANDLE)->iic_read = FUC
```

### 1.4 驱动内部的调用方式

驱动 .c 文件永远通过句柄调硬件，不直接碰 HAL：

```c
// 驱动内部 — 不知道 HAL 是什么
static uint8_t a_ds3231_iic_read(ds3231_handle_t *handle, uint8_t reg, uint8_t *buf, uint8_t len)
{
    return handle->iic_read(DS3231_ADDRESS, reg, buf, len);  // ← 通过函数指针调
}

// 驱动内部的宏也不用 HAL 宏
#define DS3231_ADDRESS  0xD0        // 8-bit I2C 地址（和我们的 0x68<<1 一样）
```

## 二、生命周期管理

### 2.1 init / deinit

```c
uint8_t ds3231_init(ds3231_handle_t *handle)
{
    // ① 检查 handle 非空
    // ② 检查所有 6 个函数指针都已注入
    // ③ 调 handle->iic_init() 初始化物理总线
    // ④ 读状态寄存器验证芯片存在
    // ⑤ 清晶振停止标志位
    // ⑥ handle->inited = 1  ← 标记已初始化
}

uint8_t ds3231_deinit(ds3231_handle_t *handle)
{
    // ① 检查 handle 非空 + inited == 1
    // ② 调 handle->iic_deinit() 反初始化总线
    // ③ handle->inited = 0
}
```

### 2.2 inited 标志的作用

驱动里每个对外函数的第一行：

```c
uint8_t ds3231_get_time(ds3231_handle_t *handle, ds3231_time_t *t)
{
    if (handle == NULL)       return 2;   // 句柄空
    if (handle->inited != 1)  return 3;   // 没初始化就调 — 报错
    if (t == NULL)            return 2;   // 输出参数空
    // ... 真正干活
}
```

## 三、错误处理体系

### 3.1 返回值约定

每个函数返回 `uint8_t`，含义统一：

| 返回值 | 含义 |
|:------:|------|
| 0 | 成功 |
| 1 | 操作失败（硬件无响应） |
| 2 | 参数非法（handle 或输入指针为 NULL） |
| 3 | 状态非法（没初始化就调了） |
| 4 | 数据非法（时间值越界） |

### 3.2 错误传播

每一层都把错误原样传回去：

```c
res = a_ds3231_iic_write(handle, REG_SECOND, bcd);
if (res != 0) {
    handle->debug_print("write second failed");
    return 1;   // ← 不吞错误，立即返回
}
```

## 四、数据封装

### 4.1 时间结构体

```c
typedef struct ds3231_time_s {
    uint16_t year;           // 如 2026
    uint8_t  month;          // 1~12
    uint8_t  week;           // 1~7
    uint8_t  date;           // 1~31
    uint8_t  hour;           // 0~23
    uint8_t  minute;         // 0~59
    uint8_t  second;         // 0~59
    ds3231_format_t format;  // 12H 还是 24H
    ds3231_am_pm_t am_pm;    // AM 还是 PM
} ds3231_time_t;
```

使用者不需要知道 BCD 编码、寄存器布局——全被封装在驱动内部。

### 4.2 get_time / set_time 对称设计

```c
ds3231_get_time(&handle, &t);   // 读时间 —— 填结构体
ds3231_set_time(&handle, &t);   // 写时间 —— 从结构体取
```

入参和出参是同一个类型，调用者不需要关心内部寄存器布局。

## 五、设计模式总结

| 模式 | 实现方式 | 好处 |
|------|---------|------|
| **依赖注入** | 函数指针注入 | 换 MCU 只换注入函数，驱动代码 0 改动 |
| **生命周期** | init/deinit + inited 标志 | 防止未初始化调用，资源管理清晰 |
| **防御式编程** | 每个函数入口检查 handle + inited + 参数 | 不会出现"野指针静默执行" |
| **错误传播** | 每层都返回错误码，不吞错误 | 出问题时能从最外层知道哪一步挂了 |
| **数据封装** | 用语义化结构体，隐藏寄存器细节 | 调用者不需要看数据手册 |
| **单一职责** | 驱动只管逻辑，硬件操作由注入函数完成 | 驱动可以脱离硬件单元测试 |

## 六、我们的项目怎么落地

已有 BSP 驱动（touch_cst816s, ds3231）和后续驱动（bme280, qmi8658, max30102）全部按此模式统一：

```
BSP 驱动标准模板:

  xxx.h:
    typedef struct xxx_handle_s {
        // 依赖注入 — 4 个函数指针
        uint8_t (*iic_read)(uint8_t addr, uint8_t reg, uint8_t *buf, uint16_t len);
        uint8_t (*iic_write)(uint8_t addr, uint8_t reg, uint8_t *buf, uint16_t len);
        void    (*delay_ms)(uint32_t ms);
        void    (*debug_print)(const char *fmt, ...);

        uint8_t inited;          // 初始化标志
    } xxx_handle_t;

    // Link 宏
    #define XXX_LINK_IIC_READ(H, F)   (H)->iic_read = F
    #define XXX_LINK_IIC_WRITE(H, F)  (H)->iic_write = F
    #define XXX_LINK_DELAY_MS(H, F)   (H)->delay_ms = F
    #define XXX_LINK_DEBUG_PRINT(H, F) (H)->debug_print = F

    // API
    uint8_t xxx_init(xxx_handle_t *handle);
    uint8_t xxx_read(xxx_handle_t *handle, xxx_data_t *data);
    uint8_t xxx_deinit(xxx_handle_t *handle);

  xxx.c:
    // 只通过 handle->iic_read/write 调硬件
    // 每个函数检查 handle != NULL && handle->inited == 1
    // 每个 I2C 操作检查返回值

使用者 (I2CSensTask):
    static xxx_handle_t s_xxx;
    XXX_LINK_IIC_READ(&s_xxx, stm32_i2c1_read);
    XXX_LINK_IIC_WRITE(&s_xxx, stm32_i2c1_write);
    XXX_LINK_DELAY_MS(&s_xxx, HAL_Delay);
    XXX_LINK_DEBUG_PRINT(&s_xxx, log_printf);
    xxx_init(&s_xxx);
```

这样 5 个传感器驱动（CST816, DS3231, BME280, QMI8658, MAX30102）都遵循同一个模式，I2CSensTask 初始化时统一注入，干净整洁。
